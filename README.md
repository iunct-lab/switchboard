# Switchboard

**A local control plane for coding agents.** One screen, one knowledge base, one ledger — for the Claude Code and Codex you are already logged into, and for your own agents.

Switchboard does not bundle any vendor CLI, does not hold API keys, and adds no approval of its own: what runs without asking is decided by the runner's permission mode (default Auto, [docs/design/permission-modes.md](docs/design/permission-modes.md)) and your answer policies. It spawns the runners you have installed, normalizes what they emit into one event vocabulary (`AgentEvent`), and gives you a task-centric UI over the top: transcript, permissions, scope, cost.

## How this repository works

This repository is a read-only copy of a private development repository: its `main` is that repository's `main` tree, sent here by a sync as one commit at a time, without the private history. Nothing is developed here.

- **Issue and pull request numbers** (`#N`) in files and commit messages refer to the private tracker and cannot be opened here.
- **Pull requests are not accepted.** A pull request opened here is answered with this policy and closed automatically.
- **Requests and bug reports** go to an Issue of the kind *Request* (the only Issue form here). A request is read and taken into the private backlog; the Issue is answered there and closed with the outcome.
- **Vulnerabilities** are reported privately through a GitHub Security Advisory: https://github.com/iunct-lab/switchboard/security/advisories/new (see `SECURITY.md`). Not in a public Issue or Discussion.
- **Questions and discussion** go to Discussions: https://github.com/iunct-lab/switchboard/discussions

## Why

Terminal-based agents are flexible, but the person ends up doing the routing (Claude or Codex?), the directory hopping, the CLAUDE.md / AGENTS.md bookkeeping, and the cost guessing. Switchboard moves those to a daemon and a thin UI, while leaving the agents themselves untouched.

## Architecture

```
apps/web            React + Vite UI, served by the daemon; a browser tab or a home-screen app (PWA). No desktop shell
packages/core       Bun daemon: HTTP + WebSocket API, sqlite store, task lifecycle, ledger
                    + a Task's approval wait (an SSO device code) relayed to its screen, memory only (docs/design/device-auth.md)
packages/protocol   AgentEvent / Task / RPC schemas (zod) — the one contract everything shares
packages/adapters/  Runner plugins. Any subset may be installed.
  claude/           Claude Code via `claude -p --input-format stream-json --output-format stream-json`
  codex/            Codex via `codex app-server` JSON-RPC (stdio); protocol types snapshot under src/generated (Apache-2.0, NOTICE)
  dak/              Decentralized-Agent-Kit via ADK REST /run_sse (SSE) + Workspace MCP for files; no A2A
```

The daemon registers its own repository as the **meta workspace**, so you can point an agent at Switchboard from inside Switchboard ("このアプリを改善"). A second button on any other workspace ("<name> を改善") does the same for that repository with a prefix the daemon reads off its tree (layout, CLAUDE.md / AGENTS.md, test and run commands; `GET /api/workspaces/:id/brief`); while the prompt still starts with an inserted prefix, switching the Workspace select swaps just that prefix. It is also an MCP server (`/mcp/<taskId>`, per-task token): runners without file tools touch the repository through scope-contained `fs.*` / `exec.run` tools, with approvals surfacing in the UI (`docs/design/workspace-mcp.md`).

**No desktop shell (Tauri is not adopted, decided 2026-10-11).** The proposal's Phase 2 wrapped this UI in Tauri 2; that plan is dropped, not moved to a later phase (#1145, answer A). Why: the browser UI already covers what the shell was for — it installs as a PWA on a desktop or a phone, the daemon runs from an immutable release promoted only after it boots, and the rescue page (`sb-rescue`) undoes a bad update from any browser (`docs/design/releases-and-rescue.md`); terminal notifications are their own PBI (#1138). What it has to reach: you send a request about Switchboard from its own browser UI and the change reaches the running daemon. The design-side record is `docs/design/proposal.html` §5 (デスクトップシェル).

## Run

```bash
./scripts/setup.sh        # installs Bun if needed, then `bun install`
bun run dev               # core on :47831, web on :5173
open http://localhost:5173
```

The built UI the daemon serves (`bun run --cwd apps/web build`, then `http://localhost:47831/`) can be added to a phone's or desktop's home screen as an app (PWA; needs HTTPS or localhost) and opens on 承認 (`/approvals`), the unanswered permission asks of every task. From a phone over Tailscale: `docs/design/mobile-approval.md`. While it is open, tool approvals and 要対応 also show as OS notifications (設定 → 端末通知, #1138).

Releases with a rescue page: run the daemon from an immutable release under `sb-rescue`, promote a commit only after it booted on a spare port, go back automatically or with one button from a phone-sized page that works while Switchboard is down, opened from 救援画面 at the top right of every screen (`docs/design/releases-and-rescue.md`; every green merge on `main` gets a `vX.Y.Z` tag and Release, and the backlog sweep promotes the newest tag by itself and holds when it did not start — Tags and unattended updates).

設定画面: the 設定 tab keeps the saved defaults in one place (approval mode, auto-resume, shadow, LLM suggestions, the turn judge, the backlog sweep) and 自動で始まる Task の既定: the runner and model the backlog stage buttons and the feedback button start their Tasks on, and 上限のときの代わり: an order of other runners (and the usage, default 0.9, at which to switch) that those Tasks and scheduled ones start on, on their CLI default model, while the decided runner is at its usage limit — the Task's transcript says so; empty switches nothing (`docs/design/rate-limit-resume.md`); 種類ごと (per kind: すぐ直す, 要望として登録, PBI にする, Task に分解, 実装, 状況確認, 閉じる) a line reads 共通 until you open it with 変える and change its runner, model or effort (opening alone saves nothing); that kind's own choice then wins, and a kind left on 共通 starts on the common one (バックログを進める: on the schedule's); a schedule has its own model, and a new schedule's runner / model start from that default (`docs/design/feedback.md`, `docs/design/backlog.md`); three more cards hold values you may want to tune while running, each with its default shown and 既定に戻す per card (#835) — 使用量と自動再開: the usage (of the runner a stage Task starts on) at which バックログを進める holds back to one stage Task overall, the automatic resume's first wait when no reset time is known and how long that wait may grow, how many usage-limit stops in a row it resumes after, the text it sends (after the fixed `[Switchboard 自動再開]` head), how many daemon stops in a row a Task is continued after (`docs/design/rate-limit-resume.md`), and the record count under which the Ledger's runner comparison calls a row too thin; 判定と自動選択: the runner / model asked when the judge's runner cannot answer (both the turn judge and the rubric judge), the turn judge's timeout (`docs/design/task-outcome.md`), and how long Workspace の自動選択 may take before it asks you to pick (`docs/design/llm-routing.md`); 新規作成の既定: the runner Home's creation form starts on and the cron a new schedule starts with, and 思考の深さ (thinking effort) — chosen per task on Home, per schedule, and in 自動で始まる Task の既定, from the runner's own list (`efforts` on `/api/health`): Claude Code gets `--effort <value>`, Codex the `effort` of every `turn/start`; empty is the CLI's own default, DAK decides it itself; it is fixed when the task is created and shown on the Brief.

Moving the history to another machine (`docs/design/cloud-hosting.md` §5): `bun packages/core/src/main.ts export <out> [--encrypt <age recipient>]` on the old one, then `bun packages/core/src/main.ts import <file> [--identity <age key file>]` into an empty HOME on the new one (same absolute paths; nothing is rewritten).

For a new Claude task, Home's execution location defaults to **Local**. Choose **Cloud**, explicitly select its Workspace, review the repository/branch and automatic Bundle transfer notice, then Start. Continue through the Task's **公式Cloudで続ける** link; launcher exit does not mean Cloud completion. Local options, attachments and shadow runs are not forwarded. See [Cloud usage and transfer contract (Claude Code on the web)](docs/design/claude-cloud.md) for setup, Private access, transfer scope and validation limits.

Cloud runs on the official cloud infrastructure. `--remote-control` lets another device operate a locally running session. To continue an existing Cloud Task locally, select **ローカルで続ける** in its detail, then answer the official CLI prompts in Terminal on the Switchboard host and saved cwd. Use the same subscription account/repository and a pushed Cloud work branch; protect dirty/untracked files yourself. After Terminal ends and the Local history is confirmed, open the linked **Local Task** and reply to use ordinary `--resume`. The original Cloud Task remains available, and later Local conversation is not automatically synced to Cloud. Opening/reloading Terminal does not start Teleport. The integrated live-account acceptance run remains pending; see the [Teleport contract and validation scope](docs/design/claude-cloud.md#continue-an-existing-cloud-task-locally-1107).

Runners are detected on `PATH`. Install them with the vendors' official installers:

- Claude Code — https://claude.com/claude-code
- Codex CLI — `curl -fsSL https://chatgpt.com/codex/install.sh | sh` (https://developers.openai.com/codex/cli).
- DAK — `docker compose up` in the Decentralized-Agent-Kit repository; the adapter talks to its agent at `http://127.0.0.1:8000` (`SWITCHBOARD_DAK_URL`). See `docs/design/dak-adapter.md` for letting it reach the repository through Workspace MCP.

## Develop

```bash
bun test                  # recorded-replay tests for adapters + daemon lifecycle tests
bun run typecheck
bun run licenses:check    # every dependency's license against scripts/licenses.allow.json (docs/design/licenses.md)
bun run codex:types      # refresh the Codex protocol type snapshot (needs codex, or CODEX_TS_DIR)
bun run core              # daemon only, with --watch
bun run web               # UI only
```

The replay tests read recordings kept outside Git (`~/.switchboard/fixtures` or `SWITCHBOARD_FIXTURES`; record your own with `.claude/skills/runner-adapter-recording/SKILL.md`); without them those tests skip with a reason, so a green CI on the public copy does not show that replaying real runner output was tested.

Development follows a PBI → Task flow without sprints; the steps are the shared skills under `ops-kit/skills/` (copied into each repository, this one included, when a task's runner starts — `docs/design/skill-sync.md`; this repository's own three stay in `.claude/skills/`) (`request-to-backlog` → `pbi-to-tasks` → `task-to-pr` → `cross-runner-review` → `review-triage-and-merge`, or `/pbi-complete <PBI>` for the whole run; rules in `issue-workflow`). This repository's own values (tests, worktrees, the Project) are in `CLAUDE.md`. The backlog tools are `ops-kit/` (`bun ops-kit/src/cli.ts --help`), shared with other repositories; `scripts/setup/*.sh` are thin entries that run it with this repository's `ops.config.json`. To start a new repository, see `docs/design/new-repo.md` (what it needs and when it is ready to start).

Data lives in `~/.switchboard/` (override with `SWITCHBOARD_HOME` — the UI footer shows the directory actually in use, and the daemon warns at boot and in the UI when it is under a temp folder, because a later start without the same `SWITCHBOARD_HOME` shows none of what was recorded there; tasks a previous daemon left running or waiting are closed as aborted at boot, with a note, and can be resumed by replying): the sqlite index/ledger, `token` (local API token, only enforced off-loopback), optional `routing.yaml` / `mcp.yaml` / `pricing.json` overrides (runner routing is a rule table; which Workspace a request goes to, when none is picked, is one LLM turn recorded in `tasks.workspace_reason`) (the price table is data; Codex usage is priced from it, subscription runners show 実課金 0; price rows entered on the settings screen sit over it and take effect without a restart), and `attachments/` — files attached to turns, one folder per task, never inside a repository (`docs/design/attachments.md`), and `artifacts/` — copies of the reports registered on the Task screen (`docs/design/artifacts.md`). Knowledge (rules, commands, notes) is a Markdown folder at `~/Knowledge` (`SWITCHBOARD_KNOWLEDGE`). Runner sessions stay where the runner keeps them (`~/.claude/projects/...`), so `--resume` works. The daemon also reads that folder (`SWITCHBOARD_CLAUDE_PROJECTS`; every `SWITCHBOARD_HISTORY_POLL_MS`, default 30 s, and on 今すぐ取り込む) and imports Claude Code sessions run in a terminal under a registered workspace as tasks with `origin: terminal`, so terminal history shows in the same list, transcript and ledger (`docs/design/claude-history-import.md`).

## Design rules

- **System ENABLES, Agent DECIDES, User APPROVES.** Users select the permission mode. Auto delegates risk decisions to the runner (Claude's classifier, Codex's auto-review); approved operations can run without a human prompt. Manual modes surface approval requests in the UI. Unconditional full access is never the default. Modes are selectable per task and changeable while it runs (`docs/design/permission-modes.md`).
- **Runners are optional plugins.** The daemon boots with any subset. No runner code is vendored; the only third-party material is the Codex protocol's generated type definitions (see `NOTICE`).
- **Text stays text.** Knowledge is Markdown in a git repo you own; sqlite is its index, the ledger, and the source of truth for the backlog (Issues and Projects; GitHub is kept in sync with it) — never committed to a source repository. Materialized to user-level files (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.claude/commands/`), never into a repository.
- **No keys, no telemetry. Your own login, on your own machine.** Switchboard holds no provider keys or runner credentials; when you choose Amazon Bedrock for Claude, it still holds none: the `claude` CLI reads AWS credentials the usual AWS way (`docs/design/bedrock.md`). Claude Code runs as the unmodified `claude` you installed and signed in to yourself, as a child process on your own machine, for you alone. Do not use Switchboard to serve other people through your Claude subscription; for that, use an API key (Anthropic's Legal and compliance page: https://code.claude.com/docs/en/legal-and-compliance). Terms review: `docs/design/license-review.md` (#22).
