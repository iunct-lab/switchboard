# 資料 → 発表用 HTML スライド

目的: 手元の資料（記事の Markdown と画像など）から、発表にそのまま使え、移動中にスマホでも確かめられるスライドを 1 ファイルの HTML で渡す。

## 入力と出力

- 入力: 資料の本文と画像。資料側のリポジトリの決まり（記事の書き方の決まりなど。そのリポジトリの CLAUDE.md / AGENTS.md）があれば先に読む
- 出力: 1 ファイルで完結する HTML（画像は base64 で埋め込む）。リポジトリにはコミットせず、成果物として渡す
<!-- when task=in -->
  （渡し方は成果物の登録）
<!-- end when -->
- 頼まれていない値（会の性質など）は利用者の言い方から決めない

## 雛形

同じフォルダの `template.html` を写して、`<section class="slide">` を中身に差し替える。仕組みは雛形のまま使い、毎回作り直さない。

- 1280x720 の固定の大きさで描き、画面に合わせて縮める（`#deck` は `flex:none`。外すと狭い画面で幅が縮んだうえに縮小率が掛かり、中身が崩れる）
- ← → / Space / クリック / スワイプで進む。N で発表者メモ（`data-notes`、先頭に `【分:秒】` の持ち時間の目安）、F で全画面。印刷すると 1 枚 1 ページ
- 縦読み: 全スライドを上から並べ、段組みを 1 段にし、文字を読める大きさに揃える。タッチ端末の縦持ちか幅 700px 未満なら自動でこのモードで開く。右上のボタンで切り替え、URL の `?read=1` / `?read=0` でも指定できる
- 使える部品（クラス）: `title` / `section`（章扉）、`tag`、`cols`（2 段。`wide` / `narrow` で幅の比）、`grid2` / `grid3` と `card`、`kpis`、`num-big`、`flow`、`table`（`compact` / `tight`）、`shot`（画像）と `cap`、`quote`、`callout`、`bar-row`、`links`、`foot`。新しい部品を足したら、縦読み（`body.read …`）での大きさも足す
- グラフは、グラフを描くスキル（dataviz など）があればその配色と検査に従う

## 決まり（利用者の指摘から）

1. **構成**: 資料の事例を並べて紹介するだけにしない。資料に共通する論点を見つけ、主題の側を軸に筋を組む。見せ方が軽くても、内容を浅くしない
2. **余計なことを書かない**: 資料に無い言い回し・推測・拡大解釈・演出（対比を作る、評価を足す、決め台詞）を入れない。数字・日付・理由は資料の文どおりに書く
3. **文章量**: 1 枚に書きすぎない。発表者メモも同じ基準で書く
4. **決めていないことを決めない**: 会の性質（LT など）を利用者の言い方から決めて、スライドに表示しない
5. **スマホで見られる**: 発表は PC でも、スマホで確かめられる形にする（雛形の縦読みを外さない）
6. **資料側の決まりを当てる**: 資料側のリポジトリの書き方の決まりがあれば、スライドとメモの文にも当てる

## 手順

1. 資料と資料側の決まりを読み、資料に共通する論点を書き出す。筋（章立て）と各章の持ち時間を決める
2. 作業ファイルは `W=$(mktemp -d)` の下に置く（固定の名前の一時ファイルを使わない）。`template.html` を写し、1 枚ずつ書く。数字・固有名詞は資料の文と突き合わせる
3. 画像を base64 で埋め込み、1 ファイルにする
4. 確かめる（headless の Chromium など）:
   - スライド表示: 全スライドを 1280x720 で撮り、はみ出し・重なりを目で見る（`#N` で N 枚目を開ける）
   - 縦読み: 幅 412px 前後で `?read=1` を開いて全体を撮り、題が読めるか・横にはみ出さないかを見る
5. 決まり 1〜6 を 1 行ずつ見直してから渡す
