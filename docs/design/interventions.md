# interventions（人の介入を数え、手間が減ったかを比べる）

人が Switchboard に手を入れた回数（承認・判断・再開）と、作業が止まった理由を、Backlog の画面の「介入（直近 7 日 / 30 日）」で見られるようにする（PBI #651、元要望 #934）。手間を減らす手を打ったとき、前の期間より減ったかを数字で確かめるため。段ごとの時間は [flow-metrics.md](flow-metrics.md)。

## 何を介入として数えるか

介入の表は作らない。Switchboard の記録（Task と events）と、取り込んだ Issue の写し（[backlog.md](backlog.md) の「保存（#885）」）から、見るたびに数える。GitHub は呼ばない（`GET /api/interventions`）。

| 種類 | 数えるもの | 根拠（`ref`） |
|---|---|---|
| 承認 | Task の `permission.resolved` で `by: "user"` のもの（利用者が許可 / 拒否した） | `task:<id>#seq:<n>` |
| 判断 | Issue の写しで `## 回答` で始まるコメント、と Task の 2 通目以降の利用者の発言 | `comment:<node id>` / `task:<id>#seq:<n>` |
| 再開 | ボタンで始めた工程の Task（`stage_issue` があり `scheduleId` が無い） | `task:<id>` |

- **数えないもの**: `rule`（保存した方針）・`timeout` の `permission.resolved`、`[Switchboard 自動再開]` で始まる発言、Task の最初のプロンプト（依頼そのもの）、バックログ次（backlog-next）が始めた工程（`scheduleId` がある）。dak がターンの終わりや中断で開いたままの確認を閉じる `permission.resolved` は `timeout`（人の回答ではない）
- **同じ操作は 1 回**: 同じ Issue・同じ本文の `## 回答` は 10 分以内、同じ Task・同じ本文の発言と同じ Issue の手動開始は 60 秒以内なら 1 回。本文は Switchboard が足す操作の印（`switchboard-op`）を除いて比べる。同じ承認は 2 度目を 409 で断るので 1 件。1 つの発言が chunk に割れていれば（seq が続く）1 通
- **PBI への帰属**: Task はタイトルの `#N ` か `stage_issue` で Issue を、写しの `parent` で PBI を引く。Issue を名指さない介入（Issue と関係の無い Task の承認など）は PBI に属さず、合計にだけ入る

## 再質問と「自動再開できなかった」

停止は Task の `stop.record`（[repeated-stops.md](repeated-stops.md) の系列、`stopKey`）から読む。別の判定は作らない。

- **再質問**: 期間内に始まった停止のうち、人の要る理由（`NEEDS_PERSON`: auth / permission / input / decision / unknown）で、**同じ系列に、それより前に回答がすでにある**もの。回答のあとに同じ理由で止まり直したことを指す。回答は Switchboard が見たもの（`seq:`）だけ数える。Issue のコメントを指す URL は実行環境の申告で、確かめていないので数えない（[repeated-stops.md](repeated-stops.md)）。文面が似ていても理由が違えば別の系列（数えない）
- **自動再開できなかった**: その停止が `exhausted` / `waiting` のまま、または停止から解消（最後の記録）までの間に、同じ Issue か Task への介入があったもの。`resolved` で、その間に介入が無ければ自動で進んだとみなす（解消のあとの別の介入は関係させない）
- **依存解消後の手動再開**: 再開のうち、直前の `/pbi-complete` の終了コメントの `waits=` / `overlap=` の相手が全部、その開始より前に閉じた（PR はマージされた）もの。開始より後に閉じた・まだ開いていれば数えない。相手の写しが無い、閉じた時刻を持たないときは**不明**

## 期間と母数

- 期間は 7 日と 30 日の固定。直近は `[now − d, now)`、その前は `[now − 2d, now − d)`。境界の時刻は新しい方に入る。任意の範囲は指定できない
- **完了までの介入（PBI 1 件あたり）**: 期間内に閉じた PBI だけが母数。その PBI に付いた全期間の介入の合計 ÷ 件数。母数が 0 なら「不明」
- **今週の介入・停止の内訳**: 未完了の PBI も含める。画面の「完了した PBI n 件（不明 m 件）· 未完了 k 件の介入 x 回」で、完了済みと未完了を混ぜずに読む

- **理由の内訳も前の期間と比べる**: 理由ごとに直近の回数、その前の回数、差を出す。その前にだけあった理由も行に残す（直近 0 回）。自動再開できなかった数と根拠のリンク（Issue と Task）は、直近とその前の両方を出す

## 不明になる場合

不明は 0 と書かず、足りない理由を数に添える。補完しない。

- 一度も取り込んでいない workspace（source が無い、最初の取込みが済んでいない）— 回答コメントが写しに無いので、その workspace 全体が不明
- 写しに無い Issue、または親の PBI が写しに無い Task に当たる介入 — どの PBI かを言えないので、合計に入れず不明に数える
- 閉じた時刻（`closedAt`）を持たない写し（この機能より前に保存した行）— 次の取込みで入る。それまで、その PBI は期間に置けず「完了した PBI（不明）」に数える

画面は、不明がある間は「数えられなかった場所が n 件あります。上の数は『それ以上』で、増減は出しません」と出し、件数を「n 以上」、差を「—」にする。数えられなかった場所には時刻が無く、どちらの期間にも入りうるので、増減は言えない（取り込みが済む・写しが揃うと出る）。前の期間の母数の行（完了した PBI の件数と不明）も直近と並べて出す。
