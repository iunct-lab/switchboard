# What leaves the machine

This is the list of everything Switchboard, the runners it starts and the scripts it ships reach over the network, so that you can decide whether to use it in your own environment without reading the code. Each row says where it goes, what is sent, when, whether it is on by default, what kind of destination it is, and how to stop it.

The kinds:

- `chosen service`: a destination you picked, or one that is the point of the feature: the model behind a runner, the Git host of a repository you registered, an agent server whose URL you typed, your own AWS account.
- `download`: the machine fetches software, a font or a version number. Nothing from your work is sent; the request itself (an address, a user agent) is all the server sees.
- `third party`: a report about your use that goes to a party you did not choose for it, such as a runner vendor's usage statistics. Switchboard sends none by default (see "Nothing to third parties").

Values that depend on the installation (schedule times, URLs you set, regions) are not copied here. The place that holds each one is named instead, so this list does not go stale when a value changes. Code is named by its symbol with the `file:line` where it was found; if a line has moved, search for the symbol.

## Nothing to third parties

By default Switchboard sends nothing to a `third party`. The only rows of that kind are the runner CLIs' own usage and error reports, and `Settings.outbound.runnerTelemetry` (`packages/protocol/src/model.ts:961`) keeps them off:

- With it off, the Claude adapter starts `claude` with `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING` and `DISABLE_AUTOUPDATER` set (`telemetryEnv`), and the Codex adapter starts `codex app-server` with analytics and feedback switched off (`telemetryArgs`). The auto-mode classifier is a model call, not telemetry, and keeps working.
- The classifier log is a separate switch, `Settings.outbound.classifierLog`, also off by default. It points Claude Code's OpenTelemetry logs at the daemon's own loopback port and nowhere else (`docs/design/claude-otel.md`), so turning it on sends nothing out of the machine.
- A database that already ran Tasks before the two switches existed keeps what it sent until then: its first start after the change turns both on once, and they can be turned off in Settings (`packages/core/src/db.ts`, the migration of Settings `outbound`).

If you turn the runner switch on, Claude Code's usage and error reports go to Anthropic and Codex's analytics and feedback go to OpenAI, as each CLI decides, and Claude Code's auto-updater runs again. They take effect for the Tasks started after the change.

Runners on Amazon Bedrock: when you switch a runner to Bedrock, its model calls go to Bedrock in the region you chose, with the AWS credentials the CLI finds the usual AWS way; Switchboard holds none (`docs/design/bedrock.md`). In an environment closed to everything but Bedrock, leave the runner switch off.

The Git host is your choice. A Workspace registered as not linked to GitHub keeps its Issues and Project inside Switchboard and sends nothing to GitHub for the backlog. The flow view and a question that names a PR are gated differently and can still read GitHub with `gh` (see their rows above, and the README, "Try it on one repository"). A Task you run in it can of course still use whatever `git` remote the repository has.

The rows of kind `download` carry none of your work. Those that run by default are the Google Fonts request of the Web UI, Codex's own update check, if Codex runs one when a Codex Task starts (its row above; you can switch it off in Codex's config), and the sign-in or fetch of whatever the machine needs when you set it up.

## Check it yourself

Point everything at a proxy that records destinations. `HTTPS_PROXY` / `HTTP_PROXY` are honoured by the daemon (Bun), `gh`, `git` and the runner CLIs; give the browser the same proxy with `--proxy-server`. A proxy that only logs each `CONNECT host:port` and each plain-HTTP request line is enough: it needs no ability to read the traffic. Start the daemon behind it, open Home, Backlog, Ledger and Settings, run one Task, and read the log. Every host should be a `chosen service` or `download` row of the table above. A host that fits no row is a gap in this document or a bug.
